# 2026-10-30：OpenVINO の非同期と、重みの 8bit・4bit 量子化

## やったこと
- `scripts/quantize_ov.py` で、fp16 の IR の重みを NNCF で量子化した（データを使わない、重みだけの量子化）。
  - int4_asym：既定の group size 128 は、チャネル数（960・480・320）を割り切れずに失敗した。32 にした。322 MB。
  - int8_asym：525 MB。公開の w8a16 は CPU で読めないが、こちらは CPU でも動く。
- `scripts/run_overnight.sh async int4_b w8a16_b quant_a curve tables` を回した（02:10〜06:37）。遅延 1000 ms の点は、下の不具合を直してから回し直した（〜07:06）。

## 結果（詳しくは `reports/report.md` の 5.1・5.2・5.4節）

| 設定 | 成功率 | 推論 p50 |
| --- | --- | ---: |
| 同期、OV GPU f16、w8a16 | 0.96（48/50） | 783 ms |
| 同期、OV GPU f16、fp16 | 0.94（47/50） | 884 ms |
| 同期、OV GPU f16、int4 | 0.70（35/50） | 786 ms |
| 非同期、実測の遅延、threshold 20 | 0.66（33/50） | 801 ms |
| 非同期、実測の遅延、threshold 10 | 0.02（1/50） | 809 ms |

- 遅延許容曲線（非同期、threshold 10）：0 ms で 0.96、500 ms で 0.66、1000・1500・2000 ms で 0。
- モードA（3周の中央値）：GPU は int8 が 782 ms、int4 が 803 ms。CPU は int8 が 1817 ms、int4 が 1894 ms（fp16 の IR は 2934 ms）。

## ハマったこと（直したもの）
- 遅延 1000 ms の非同期で、グリッパの出力が -1.102 になり、行動の範囲の確認で評価が止まった。遅延が大きいと、チャンクの後ろのほうの行動を使うためと考えられる。グリッパは符号で開閉が決まるので、範囲を確かめずに丸め、確認は腕の6次元だけにした（PR #20）。
- 系列が 7 つになると、パレート図のマーカーの形（5 種類）が足りずに落ちた。12 種類にして、繰り返して使うようにした（PR #21）。
- 非同期では、待っている時間（hold）も 280 ステップ（14 秒）の制限に数える。遅延 1000 ms 以上の 0 は、すべて時間切れだった。

## 見張り
- 長時間の実行は、`setsid` で起動し、PGID で管理した。
- 見張りのスクリプトは、次のどれかで知らせる：完了、プロセスが消えた、ログが 20 分伸びない、失敗の行が出た、1 時間たった。
- 夜間に、失敗が2回あった（上の2つ）。どちらも原因を直して、測り直した。
