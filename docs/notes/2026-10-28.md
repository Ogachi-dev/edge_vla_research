## ハマったこと（直したもの）
- torch：重みが bf16 で読まれ、fp32 を指定しても bf16 のまま動いていた（1回 20 秒）。fp32 は float32 に変換する。
- OV（physicalai）：公開版の manifest の `ActionChunkTrimmer`（n_action_steps=1）が先頭の1行だけを返していた。外して 50×7 を使う。
- vla-server：チェックポイントは `-m` ではなく位置引数。OV の `setupvars.sh` がラッパーの引数を消費していた。
- LIBERO：グリッパの出力が ±1 を少しはみ出す（-1.024）。0.1 まではクリップする。
- MuJoCo の描画は `MUJOCO_GL=glfw` だけ動いた（egl・osmesa は失敗）。
- `os.sched_getcpu` は Python 3.12 にない。psutil で取る。

## 一致チェック（`reports/equivalence_libero.md`）
- OV の CPU 版と GPU 版は互いにほぼ一致した。PyTorch とは cosine 0.72、グリッパの符号の反転が 15 回あった。
- OV の IR は固定ノイズを入力に取らないので、ノイズの違いの可能性が高い。ただし、成功率で確かめる。

## 明日やること（パラメータの調整）
夜間の実行が終わったら `python scripts/make_report_tables.py` を実行して、`reports/` の表と図を見る。その後、1つずつ `--set` で変えて試す。

| 変えるもの | 例 | 効くところ |
| --- | --- | --- |
| CPU のスレッド数 | `--set policy.n_threads=16`（vla.cpp も同じ） | torch・OV CPU・vla.cpp CPU のモードA |
| OV の重み | `--set policy.model=data/models/ov/smolvla-libero-w8a16-ov` | OV の速さ・成功率 |
| vla.cpp の重みの型 | `--set 'server.args=["--weight-dtype","f16"]'` | vla.cpp（この CPU は bf16 の演算を持たない） |
| flow matching のステップ数 | `--set policy.num_steps=5`、vla.cpp は `server.args=["--num-steps","5"]` | 速さと成功率の取り引き |
| 実行ホライズン | `--set executor.n_exec=25` | モードB・C |
| 遅延（仮想時間） | `--set latency.ms=1000` | モードCの遅延許容曲線 |
| エピソード数 | `--set task_ids=[0,1,2] --set episodes_per_task=2` | 試すときは減らす |

```bash
source .venv-bench/bin/activate   # ROS のシェルは使わない
```
